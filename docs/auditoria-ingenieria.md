# Auditoría de ingeniería de BLANDSKRON.cl

Revisión del 11 de noviembre de 2026. La línea base se obtuvo del commit 1ca1ecb de main, con árbol limpio. La versión inicial ya servía HTML estático, TypeScript para la mejora progresiva del menú, activos versionados con Vite, fuentes WOFF2 locales y 22 pruebas con Playwright y axe. Se inspeccionaron las cuatro entradas HTML, los tokens y estilos, la compilación, el código de navegación, la configuración de contacto, las dos variantes de hosting, el workflow, el lockfile y la documentación.

## Hallazgos y decisiones

| Prioridad | Hallazgo reproducido                                                                                                                                                      | Decisión y evidencia                                                                                                                                                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1        | En producción, HTTP, HTTPS con www e index.html responden 200. La portada HTTPS carece de CSP, HSTS, nosniff, Referrer-Policy, Permissions-Policy y protección de marcos. | Las reglas correspondientes están preparadas para LiteSpeed. La vista previa verifica alias, política CSP y 404 real. La instalación en cPanel y su verificación externa quedan pendientes.                                                                    |
| P1        | Al tabular más allá del último enlace del menú móvil, el menú permanecía abierto sobre la portada.                                                                        | Cierra al salir el foco sin impedir la navegación nativa con teclas modificadoras. La prueba existente recorre todos los enlaces y verifica que el foco llegue al primer botón de portada con el menú cerrado.                                                 |
| P1        | La ejecución CI dependía de etiquetas mutables de GitHub Actions y dejaba las credenciales del checkout disponibles en el repositorio temporal.                           | Se fijaron los SHA de checkout v6.1.0 y setup-node v6.5.0, se deshabilitó la persistencia de credenciales y se conservó contents: read. CI ejecuta Lighthouse sobre la compilación. [GitHub](https://docs.github.com/en/actions/reference/security/secure-use) |
| P2        | Las fuentes se descubrían tras la hoja CSS y la carga desplazaba los botones de portada.                                                                                  | Precarga de Manrope e Inter en la portada, con las mismas URLs que usa CSS. Vite resuelve los nombres versionados y Chromium pide una vez cada fuente. JetBrains Mono conserva su carga desde CSS.                                                             |
| P2        | Los enlaces de proyectos tenían nombres genéricos fuera de su tarjeta.                                                                                                    | El texto visible identifica Agnara y el agente documental, y las flechas decorativas salen del nombre accesible. Se conservaron los destinos y el diseño.                                                                                                      |
| P3        | Existían opciones de añadir manifiestos para agentes, analítica, monitores, más dependencias o un nuevo sistema de diseño.                                                | El contenido ya es legible en HTML. La landing tiene enlaces y carece de herramientas interactivas propias que justifiquen WebMCP. Se conservan las fuentes existentes y la infraestructura simple.                                                            |

No se identificó un P0 dentro de la revisión realizada. Los problemas de hosting se mantienen como P1 abiertos. El sitio publicado ya presenta ambas páginas legales como borradores, con canonical y noindex. No se hizo push ni se alteraron el alojamiento o el DNS durante esta revisión.

En privacidad y términos, ambas ejecuciones móviles dieron 100 en rendimiento, accesibilidad y buenas prácticas. El intento de obtener datos de campo mediante PageSpeed Insights devolvió HTTP 429 por cuota. Se midieron LCP y CLS en laboratorio, y TBT se informa como métrica separada. Para reproducir, ejecutar npm ci, npm run check, npm run audit:lighthouse -- --legal y npm run audit:lighthouse -- --agentic. El comando con --agentic sobrescribe los informes de portada en docs/lighthouse. Los JSON comparables de esta revisión están en release/engineering-baseline y release/engineering-after. ## SEO y navegación por agentes

El HTML inicial contiene los servicios, proyectos, contacto, títulos, descripción, Open Graph, Twitter Cards, canonical y enlaces legales. La portada, las dos páginas legales y el 404 pasaron html-validate y el validador HTML del W3C sin errores. El grafo de Schema.org pasó con seis elementos de nivel superior y cero errores o advertencias. El sitemap publicado contiene la portada. Los repositorios GitHub enlazados respondieron 200. El número empresarial configurado conserva su enlace directo con texto inicial, y wa.me respondió 302 a la ruta de WhatsApp del número. No se envió un mensaje.

Las páginas describen software a medida, aplicaciones y sistemas empresariales, integración mediante APIs, asistentes y agentes, automatización, seguridad y consultoría. La muestra cualitativa previa de intención está en docs/seo.md. Volumen, posiciones, consultas orgánicas propias, propiedades de Search Console y Bing Webmaster Tools y citas de IA quedaron sin verificar por falta de acceso. ## Seguridad, privacidad y producción

DNS devolvió el dominio canónico y un alias www hacia el mismo sitio. El origen visible respondió LiteSpeed y comprimió la portada con gzip. Ambos nombres negociaron TLS 1.3 y presentaron un certificado aceptado por el cliente, emitido por Let’s Encrypt y con vigencia observada hasta el 11 de diciembre de 2026. CDN, renovación efectiva y permisos del panel quedan sin verificar. Una URL inexistente devolvió 404 con la página genérica de LiteSpeed. La plantilla preparada permite servir el 404 corporativo. El paquete de cPanel incluye solo la salida pública para el sitio y deja la plantilla de reglas por separado.

npm ci reinstaló las dependencias fijadas por el lockfile y npm audit devolvió cero avisos conocidos. Se conservaron los permisos de solo lectura de CI y se redujo la exposición de credenciales del checkout. Las 22 pruebas finales pasaron, incluidas axe, sin JavaScript, reflujo, foco, robots, sitemap, JSON-LD, HTTP, CSP y el flujo de WhatsApp. Se comprobó el comportamiento con el canal apagado en una compilación aparte. Se revisaron capturas a 375, 768 y 1.440 px y el árbol de accesibilidad. Con latencia emulada de 150 ms, bajada de 1,6 Mb/s y JavaScript desactivado, la portada y los enlaces cargaron sin solicitudes fallidas. Lighthouse también se ejecutó con el Chromium de Playwright que usa el workflow. No se modificó el lockfile ni se añadieron dependencias.

Las páginas legales identifican a BLANDSKRON SpA, correo y canal de derechos, finalidades, categorías de datos, proveedores por confirmar y criterios de conservación. El inventario técnico sigue sin evidencias de analítica ni rastreo previo a WhatsApp. Falta confirmar responsables, registros, retención, transferencias, proveedores y bases específicas antes de aprobar. La BCN mantiene el 1 de diciembre de 2026 como fecha de vigencia general de la reforma de la Ley 21.719 en las fuentes consultadas. La propuesta de postergación se debe contrastar de nuevo al momento de publicar. La aplicabilidad de la Ley 19.496 depende de cómo se contrate efectivamente el servicio. ## Cambios y comprobaciones para desplegar

- **.github/workflows/quality.yml** fija las revisiones y agrega la ejecución de Lighthouse. **scripts/lighthouse.mjs** habilita la categoría experimental bajo demanda y exporta métricas adicionales. **README.md** y esta auditoría documentan los comandos y el alcance.
- [ ] Respaldar el document root y el .htaccess activo. Confirmar la terminación TLS y probar en staging la fusión de las reglas LiteSpeed. Mantener los borradores fuera del sitemap hasta la aprobación.
- [ ] Verificar en el origen 200 canónico, 301/308 de HTTP/www e index.html con ruta y consulta, 404 corporativo real, compresión y política de caché. Confirmar que los assets CSS y JS carguen bajo CSP. Activar HSTS cuando se verifique la ruta HTTPS.
- [ ] Revisar DNS y certificados con el titular del hosting. Usar comprobaciones periódicas sencillas para estado HTTP, vigencia TLS y sitemap. Consultar logs de 404 y conservar el respaldo para revertir si falla el despliegue.
